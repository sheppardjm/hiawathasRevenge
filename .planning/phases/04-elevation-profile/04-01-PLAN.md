**Step 1: Create `src/components/ElevationProfile.astro`.**

This is a plain .astro component (NO client: directive — lazy-init is handled manually in the script block). Follow the same pattern as RouteMap.astro.

**Component structure:**

**Frontmatter (---):** Empty or comment-only. No server-side imports needed.

**Template:**
```html
<div id="elevation-chart-container" class="relative w-full h-[140px] sm:h-[180px]">
  <canvas id="elevation-chart"></canvas>
</div>
```

Key details:
- `position: relative` (via Tailwind `relative`) is REQUIRED — Chart.js reads the parent container size and requires `position: relative` on the container.
- `h-[140px]` is mobile default (< 640px). `sm:h-[180px]` applies at >= 640px (tablet and desktop). This satisfies ELEV-05.
- Height is set on the CONTAINER div, not the canvas. Chart.js with `maintainAspectRatio: false` reads the container height.
- Do NOT add width/height attributes to the canvas element.

**Script block (`<script>`):** Contains all chart logic. Structure it as follows:

**`initChart()` async function** containing:

1. **Dynamic import Chart.js (tree-shaken — NOT chart.js/auto):**
   ```javascript
   const {
     Chart,
     LineController,
     LineElement,
     PointElement,
     LinearScale,
     Filler,
     Tooltip,
     Decimation
   } = await import('chart.js');
   ```
   MUST be dynamic import inside the function (not static top-level). Static import puts Chart.js in the initial bundle, violating ELEV-04. Import ONLY the components needed for a line chart — do NOT use `chart.js/auto` which imports everything (~200KB vs ~30KB).

2. **Register Chart.js components:**
   ```javascript
   Chart.register(LineController, LineElement, PointElement, LinearScale, Filler, Tooltip, Decimation);
   ```

3. **Fetch route data and build dataset:**
   ```javascript
   const routeData = await fetch('/data/route-data.json').then(r => r.json());
   const data = routeData.points.map(pt => ({
     x: pt.miles,
     y: +(pt.ele * 3.28084).toFixed(1)
   }));
   ```
   - `routeData.points` is the array of 456 simplified points (same as RouteMap.astro uses).
   - `ele` is in METERS — multiply by 3.28084 to convert to FEET. Without this conversion, Y-axis would show ~194–294 instead of ~638–965.
   - `.toFixed(1)` with `+` coercion rounds to 1 decimal for tooltip display while keeping numeric type.
   - Data is already sorted ascending by miles (0 → 101.98), which is required for `parsing: false`.

4. **Create chart instance:**
   ```javascript
   const canvas = document.getElementById('elevation-chart');
   new Chart(canvas, {
     type: 'line',
     data: {
       datasets: [{
         data,
         parsing: false,
         borderColor: '#c8973e',
         backgroundColor: 'rgba(200, 151, 62, 0.15)',
         fill: 'start',
         pointRadius: 0,
         borderWidth: 1.5,
         tension: 0
       }]
     },
     options: {
       parsing: false,
       responsive: true,
       maintainAspectRatio: false,
       animation: false,
       plugins: {
         legend: { display: false },
         tooltip: {
           mode: 'index',
           intersect: false,
           callbacks: {
             title: (items) => `Mile ${items[0].parsed.x.toFixed(1)}`,
             label: (item) => `${Math.round(item.parsed.y)} ft`
           }
         },
         decimation: {
           enabled: true,
           algorithm: 'lttb',
           samples: 300,
           threshold: 400
         }
       },
       scales: {
         x: {
           type: 'linear',
           title: { display: true, text: 'Distance (miles)', color: '#e8e0d0' },
           ticks: { color: '#e8e0d0', maxTicksLimit: 8 },
           grid: { color: 'rgba(255,255,255,0.08)' }
         },
         y: {
           type: 'linear',
           title: { display: true, text: 'Elevation (ft)', color: '#e8e0d0' },
           ticks: {
             color: '#e8e0d0',
             callback: (v) => `${Math.round(v)} ft`
           },
           grid: { color: 'rgba(255,255,255,0.08)' }
         }
       }
     }
   });
   ```

   Critical configuration details:
   - `parsing: false` at BOTH options level AND dataset level — REQUIRED for LTTB decimation to function. Without it, decimation silently does nothing.
   - `maintainAspectRatio: false` — REQUIRED so that the CSS container height (140px/180px) controls the chart height. Default is `true` which would override the container.
   - `responsive: true` — chart redraws on container resize.
   - `animation: false` — single render pass, no transition animation.
   - `type: 'linear'` for x-axis — REQUIRED for LTTB. Do NOT use CategoryScale.
   - `fill: 'start'` — fills from the line down to the x-axis with the semi-transparent amber.
   - `pointRadius: 0` — no dots on the line (too many points).
   - `borderColor: '#c8973e'` — amber-500 accent color (project design token).
   - `tension: 0` — no curve smoothing (accurate to actual elevation data).
   - Axis label color `#e8e0d0` — cream-200 from project design tokens, readable on the dark forest background.
   - Grid color `rgba(255,255,255,0.08)` — subtle grid lines that don't overpower the chart.
   - Tooltip shows "Mile X.X" title and "NNN ft" label for easy reading.

**Lazy-init pattern** (outside `initChart()`, at module scope):

```javascript
let chartInitialized = false;
const container = document.getElementById('elevation-chart-container');

if (container) {
  const observer = new IntersectionObserver(
    (entries) => {
      if (entries[0].isIntersecting && !chartInitialized) {
        chartInitialized = true;
        observer.disconnect();
        initChart();
      }
    },
    { rootMargin: '0px' }
  );
  observer.observe(container);
}
```

Note: Unlike RouteMap.astro which uses a scroll + IO two-stage pattern, the elevation chart uses IntersectionObserver ONLY. The scroll listener on RouteMap already triggers Leaflet loading on first scroll; the elevation chart section is below the map, so IO alone is sufficient. Adding a scroll listener would cause Chart.js to load too early when the map section triggers it.

**Do NOT include (deferred to later phases):**
- Gravel sector annotation bands (Phase 5 — ELEV-02)
- CustomEvent dispatch on hover for map sync (Phase 5 — ELEV-03)
- chartjs-plugin-annotation registration or usage (Phase 5)
