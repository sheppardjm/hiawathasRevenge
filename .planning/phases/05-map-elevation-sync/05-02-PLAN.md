**Step 1: Fetch annotations.json and filter for sectors.**

After the existing `bikeMarker = L.marker(...)` block (added in Plan 01), add:
```javascript
// Fetch annotations and draw gravel sector overlays
const annotations = await fetch('/data/annotations.json').then(r => r.json());
const sectors = annotations.filter(a => a.type === 'sector');
```

**Step 2: Draw sector polylines.**

Immediately after the filter:
```javascript
for (const sector of sectors) {
  const sectorPts = latlngs.slice(sector.startIdx, sector.endIdx + 1);
  L.polyline(sectorPts, {
    color: '#c8973e',
    weight: 5,
    opacity: 0.85
  }).addTo(map);
}
```

Key details:
- `latlngs` is the existing array from `routeData.points.map((pt) => [pt.lat, pt.lon])` — already in scope from the route polyline creation earlier in initMap().
- `slice(startIdx, endIdx + 1)` — JavaScript `slice` excludes the end index. Without `+1`, the sector polyline ends one point short, leaving a visible gap.
- Color `#c8973e` — amber-500, the project's primary accent color. All sectors use the same color because annotations.json has no `difficulty` field. The roadmap says "color-coded by difficulty" but no difficulty data exists — using a single accent color is the pragmatic choice that keeps the color palette consistent with the project design tokens.
- `weight: 5` — thicker than the base route (weight: 4) so sectors are visually prominent.
- `opacity: 0.85` — slightly transparent but clearly visible over the CyclOSM tiles.
- Sectors are added AFTER `routeLine` so they render on top of the base dark green polyline.
