Create `src/components/ScrollReveal.astro` — a component with NO visible HTML (empty template), containing only a `<style is:global>` block and a `<script>` block. This encapsulates all scroll-reveal logic in one file.

**CSS (`<style is:global>`):**

```css
[data-reveal] {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity 0.6s cubic-bezier(0.4, 0, 0.2, 1),
              transform 0.6s cubic-bezier(0.4, 0, 0.2, 1);
}

[data-reveal].is-visible {
  opacity: 1;
  transform: translateY(0);
}

@media (prefers-reduced-motion: reduce) {
  [data-reveal] {
    opacity: 1;
    transform: none;
    transition: none;
  }
}
```

Use `is:global` on the style tag so the attribute selectors apply to elements across the page (not scoped to the component's own empty template).

**JavaScript (`<script>`):**

```javascript
if (!window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
  const observer = new IntersectionObserver((entries, obs) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        entry.target.classList.add('is-visible');
        obs.unobserve(entry.target);
      }
    });
  }, { threshold: 0.15 });

  document.querySelectorAll('[data-reveal]').forEach(el => {
    if (el.getBoundingClientRect().top < window.innerHeight) {
      el.classList.add('is-visible');
    } else {
      observer.observe(el);
    }
  });
}
```

Key implementation details:
- `threshold: 0.15` (not 0.3 like AnimatedDivider) because sections are tall and 30% may never be visible on mobile
- Above-fold guard: elements already in viewport on load get `is-visible` immediately with no animation
- Reduced-motion users: CSS layer shows content statically; JS layer skips observer setup entirely
- Single shared IntersectionObserver for all `[data-reveal]` targets (not one per element)
- `obs.unobserve(entry.target)` — one-shot reveal, does not re-trigger on scroll-back

Then in `src/pages/index.astro`:

- Add `<ScrollReveal />` as the LAST child before `</BaseLayout>`, after the credits/footer section

Do NOT add data-reveal attributes to any sections in this task — that happens in Task 2.

**Part B: Add stagger CSS for segment cards in RouteExplainer.astro**

In the existing `<style>` block of `RouteExplainer.astro`, add the following CSS rules for staggered card reveals. The parent section gets `data-reveal` and when it receives `is-visible`, the child `.segment-card` elements transition in with staggered delays:

```css
/* Stagger: cards hidden by default, revealed when parent section is visible */
.segment-card {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity 0.5s cubic-bezier(0.4, 0, 0.2, 1),
              transform 0.5s cubic-bezier(0.4, 0, 0.2, 1);
}

/* nth-child stagger — 100ms per card, 7 cards = 600ms max */
.segment-card:nth-child(1)  { transition-delay: 0ms; }
.segment-card:nth-child(2)  { transition-delay: 100ms; }
.segment-card:nth-child(3)  { transition-delay: 200ms; }
.segment-card:nth-child(4)  { transition-delay: 300ms; }
.segment-card:nth-child(5)  { transition-delay: 400ms; }
.segment-card:nth-child(6)  { transition-delay: 500ms; }
.segment-card:nth-child(7)  { transition-delay: 600ms; }

/* Cards become visible when parent section is revealed */
.route-explainer-section.is-visible .segment-card {
  opacity: 1;
  transform: translateY(0);
}

/* Reduced motion: cards always visible, no stagger */
@media (prefers-reduced-motion: reduce) {
  .segment-card {
    opacity: 1;
    transform: none;
    transition: none;
    transition-delay: 0ms;
  }
}
```

IMPORTANT: These stagger rules must NOT conflict with existing `.segment-card` styles. The existing styles define grid layout, border, padding — those are orthogonal. The new rules add opacity/transform/transition which are new properties on `.segment-card`. Place the new stagger rules AFTER the existing `.segment-card` layout rules in the `<style>` block but BEFORE the `@media (min-width: 768px)` responsive block.

NOTE: The reduced-motion rule for `.segment-card` should be placed alongside or after the stagger rules, not inside the existing responsive `@media` blocks.
