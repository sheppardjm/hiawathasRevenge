<task type="auto">
  <name>Task 2: Create PhotoGallery.astro with grid and lightbox</name>
  <files>src/components/PhotoGallery.astro, src/pages/index.astro</files>
  <action>
    Create `src/components/PhotoGallery.astro` following the exact Astro island pattern used by RouteMap.astro and ElevationProfile.astro (no `client:` directive — script tag handles interactivity).

    **Frontmatter section:**

    1. Import photos.json directly (NOT via Astro content collections — direct JSON import is simpler and matches the empty-array pattern):
       ```typescript
       import photosData from '../../public/data/photos.json';
       ```

    2. Define the PhotoEntry type matching the photos.json schema from content.config.ts:
       ```typescript
       type PhotoEntry = {
         id: string;
         filename: string;
         thumb: string;
         mile: number;
         lat?: number;
         lon?: number;
       };
       ```

    3. Cast and store: `const photos = photosData as PhotoEntry[];`

    4. Add dimension parser function that extracts width/height from source filenames:
       ```typescript
       function parseDims(filename: string): { w: number; h: number } {
         const m = filename.match(/-(\d+)x(\d+)/);
         return m ? { w: Number(m[1]), h: Number(m[2]) } : { w: 1536, h: 2048 };
       }
       ```
       Default fallback is 1536x2048 (the most common portrait size in the source images).

    **Template section:**

    5. Conditional render — when `photos.length === 0`, show placeholder text; otherwise show the grid.

    6. Empty state:
       ```html
       <p class="text-cream-200 text-sm italic">Photos coming soon.</p>
       ```

    7. Grid (when photos exist) — use `id="photo-gallery"` for PhotoSwipe targeting:
       ```html
       <div id="photo-gallery" class="grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-4 gap-2">
       ```

    8. For each photo, render an `<a>` anchor with PhotoSwipe data attributes. The `href` points to `/images/{filename}` (full-resolution source for lightbox). Each anchor contains a thumbnail `<img>`:
       ```html
       {photos.map((photo) => {
         const dims = parseDims(photo.filename);
         return (
           <a
             href={`/images/${photo.filename}`}
             data-pswp-width={dims.w}
             data-pswp-height={dims.h}
             data-cropped="true"
             target="_blank"
             rel="noopener"
             class="block overflow-hidden"
           >
             <img
               src={`/thumbs/${photo.thumb}`}
               alt=""
               loading="lazy"
               decoding="async"
               class="w-full aspect-square object-cover"
             />
           </a>
         );
       })}
       ```

       Critical details:
       - `data-cropped="true"` is REQUIRED because thumbnails use `object-fit: cover` (CSS crop). Without it, PhotoSwipe's zoom animation calculates the wrong origin.
       - `loading="lazy"` and `decoding="async"` satisfy PHOTO-06 (lazy-loaded thumbnails).
       - `aspect-square object-cover` creates a uniform square grid with CSS cropping.
       - Use `photo.thumb` from photos.json verbatim — do NOT re-derive the thumb filename.
       - `href` points to `/images/{photo.filename}` — the source JPGs. Phase 9 or a pipeline step will copy source images to `public/images/` for serving. Until then, the lightbox will 404 on the full image (acceptable since photos.json is currently empty).

    **Script section (PhotoSwipe lightbox initialization):**

    9. Add a `<script>` block (NOT in frontmatter — PhotoSwipe requires browser globals). Import PhotoSwipeLightbox and its CSS:
       ```javascript
       import PhotoSwipeLightbox from 'photoswipe/lightbox';
       import 'photoswipe/style.css';
       ```

       CSS import in `<script>` block is correct — Vite bundles it into the page CSS at build time. PhotoSwipe CSS is ~3KB. The "lightbox deferred" success criterion is satisfied by JS deferral via `pswpModule`, not CSS.

    10. Guard initialization with DOM element check (prevents errors when gallery is empty):
        ```javascript
        const gallery = document.getElementById('photo-gallery');
        if (gallery) {
          const lightbox = new PhotoSwipeLightbox({
            gallery: '#photo-gallery',
            children: 'a',
            pswpModule: () => import('photoswipe')
          });
          lightbox.init();
        }
        ```

        Key behaviors:
        - `pswpModule: () => import('photoswipe')` defers the 30KB PhotoSwipe core until the user clicks a thumbnail. Only click listeners are bound on `lightbox.init()`.
        - `gallery: '#photo-gallery'` + `children: 'a'` — DOM-connected gallery reads `data-pswp-width`, `data-pswp-height`, `href` from anchor elements.
        - The `if (gallery)` guard ensures no errors when photos.json is empty (the grid div is not rendered).
        - Do NOT use `astro:page-load` — this project does not use View Transitions.

    **Wire into index.astro:**

    11. In `src/pages/index.astro`:
        - Add import in frontmatter: `import PhotoGallery from '../components/PhotoGallery.astro';`
        - Add a new section AFTER the Elevation Profile section and BEFORE the Support section:
          ```html
          <section class="py-[--spacing-block]">
            <h2 class="text-3xl mb-[--spacing-element]">Photos</h2>
            <PhotoGallery />
          </section>
          ```
        - The section class and h2 styling must match the pattern used by the Elevation Profile and Support sections.

    **Anti-patterns to avoid:**
    - Do NOT import `photoswipe` or `photoswipe/lightbox` in frontmatter (causes SSR "window is undefined" error).
    - Do NOT use a `client:` directive on the component (the `<script>` tag pattern handles client-side code).
    - Do NOT use `astro:page-load` event (no View Transitions in this project).
    - Do NOT pass `dataSource` array to PhotoSwipe — DOM-connected gallery via anchor elements is simpler and correct for static rendering.
