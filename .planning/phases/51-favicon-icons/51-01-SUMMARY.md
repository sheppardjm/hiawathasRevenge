## Decisions Made
- **Inline fill vs CSS classes in generation script:** sharp's SVG renderer does not reliably process `<style>` blocks, so generate-favicons.js uses inline fill attributes on rect and path elements, while the human-readable favicon.svg uses CSS classes. Same visual result, different encoding.
- **Icon link tag ordering:** SVG first (preferred by modern browsers when type=image/svg+xml), apple-touch-icon second (iOS), ICO last with sizes="32x32" (legacy only). `rel="shortcut icon"` avoided (deprecated).
- **No dark-mode media query in favicon.svg:** The forest-green (#1a2e1a) background reads well on both light and dark browser tab bars -- no conditional styling needed.
