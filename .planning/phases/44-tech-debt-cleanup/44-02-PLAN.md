**Step B — Update `src/components/RouteExplainer.astro` rendering:**

1. In the `segmentsWithPhotos` computation (around line 30-34), also carry through the `cardPhoto` field. It already spreads `...seg` so this happens automatically, but verify it does.

2. Replace the multi-photo grid block (lines 46-62, the `seg.photos.length > 0 && (` block with `.segment-photo-grid`) with a single `<img>` that uses `seg.cardPhoto`. The new rendering should be:

```astro
{seg.cardPhoto && (
  <img
    src={seg.cardPhoto}
    alt={`${seg.name} segment`}
    loading="lazy"
    decoding="async"
    width={parseDims(seg.cardPhoto).w}
    height={parseDims(seg.cardPhoto).h}
    style={`aspect-ratio: ${parseDims(seg.cardPhoto).w} / ${parseDims(seg.cardPhoto).h};`}
    class="segment-hero-photo"
  />
)}
```

Note: `parseDims` extracts dimensions from filenames with `-WxH` patterns. For thumbs without dimension suffixes, it falls back to 1536x2048 (portrait). This is acceptable — the aspect-ratio CSS will handle display correctly regardless.

3. Remove the `.segment-photo-grid` CSS rule block (around lines 159-166 in the `<style>` section). Replace it with:

```css
.segment-hero-photo {
  width: 100%;
  height: auto;
  display: block;
  border-radius: 0.5rem 0.5rem 0 0;
  object-fit: cover;
  max-height: 400px;
}
```

This gives each card a single hero image that fills the card width, caps height at 400px to prevent overly tall portrait images from dominating, and rounds the top corners to match the card container.
