    **Step 1: Create `scripts/copy-gpx.js`**

    This script copies the smaller GPX file (`Munising_Hiawatha_s_Revenge.gpx`) from the project root to `public/` so it is served as a static asset.

    ```javascript
    /**
     * copy-gpx.js
     *
     * Copies the route GPX file to public/ for direct download.
     * Uses the smaller Munising file (~5,796 lines), not the 252k-line Hiawatha_100.gpx.
     */

    import { copyFileSync, existsSync } from 'fs';
    import { fileURLToPath } from 'url';
    import { dirname, join } from 'path';

    const __dirname = dirname(fileURLToPath(import.meta.url));
    const projectRoot = join(__dirname, '..');

    const srcFile = join(projectRoot, 'Munising_Hiawatha_s_Revenge.gpx');
    const destFile = join(projectRoot, 'public', 'Munising_Hiawatha_s_Revenge.gpx');

    if (!existsSync(srcFile)) {
      console.warn('[copy-gpx] Source GPX not found, skipping:', srcFile);
    } else {
      copyFileSync(srcFile, destFile);
      console.log('[copy-gpx] Copied GPX to public/');
    }
    ```

    Key details:
    - Use `copyFileSync` (not symlink) — symlinks break in CI/production builds (same pattern as copy-images.js from Phase 8).
    - Graceful skip with `console.warn` if GPX file is missing — pipeline does not abort.
    - Only copy `Munising_Hiawatha_s_Revenge.gpx` (5,796 lines). Do NOT copy `Hiawatha_100.gpx` (252,923 lines — too large for user download).

  <name>Task 2: Add topographic contour line pattern class to global.css</name>
  <files>src/styles/global.css</files>
  <action>
    Add a `.topo-divider` CSS class to `global.css` inside the existing `@layer base` block. This class renders a horizontal strip of repeating topographic contour lines using an SVG data URI.

    Add the following rules inside the `@layer base { ... }` block (after the existing restock popup styles):

    ```css
    /* Topographic contour divider — decorative wilderness pattern */
    .topo-divider {
      height: 60px;
      background-image: url('data:image/svg+xml;utf8,<svg xmlns="http://www.w3.org/2000/svg" width="400" height="60"><path d="M0 20 Q50 8 100 20 Q150 32 200 20 Q250 8 300 20 Q350 32 400 20" stroke="%233d6b3d" stroke-width="1.5" fill="none"/><path d="M0 35 Q60 22 120 35 Q180 48 240 35 Q300 22 360 35 Q400 42 400 42" stroke="%233d6b3d" stroke-width="1" fill="none" opacity="0.6"/><path d="M0 50 Q80 38 160 50 Q240 62 320 50 Q380 42 400 50" stroke="%233d6b3d" stroke-width="0.75" fill="none" opacity="0.35"/></svg>');
      background-repeat: repeat-x;
      background-size: 400px 60px;
      opacity: 0.7;
    }
    ```

    Key details:
    - THREE contour lines at different vertical positions (20px, 35px, 50px) with varying opacity (1.0, 0.6, 0.35) to simulate topographic depth.
    - Stroke color `%233d6b3d` is the URL-encoded form of `#3d6b3d` (forest-700). MUST use `%23` not `#` — `#` breaks the CSS `url()` parser.
    - `repeat-x` tiles horizontally for any viewport width. Height fixed at 60px.
    - Overall `opacity: 0.7` keeps the pattern subtle — "felt not seen" per research recommendation.
    - Quadratic bezier curves (`Q`) create organic contour-like undulations.
    - 400px tile width prevents visible seam repeats at common viewport widths.
    - Place inside `@layer base` so it can be overridden by component styles if needed.

    **Anti-patterns to avoid:**
    - Do NOT use an external SVG file — data URI avoids HTTP request.
    - Do NOT use `#` characters inside the SVG data URI — must be `%23`.
    - Do NOT use raster images for the pattern.
    - Do NOT make the pattern too heavy (keep opacity <= 0.7).
  </action>
