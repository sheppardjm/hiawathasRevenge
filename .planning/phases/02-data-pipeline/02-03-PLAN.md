</objective>

  <name>Task 1: Create pipeline orchestrator and wire npm hooks</name>
  <files>scripts/pipeline.js, package.json</files>
  <action>
Create `scripts/pipeline.js` as an ESM module:

1. Import `execFileSync` from `child_process` and `fileURLToPath` from `url`.
2. Resolve the project root from `import.meta.url` (scripts dir is one level up from root).
3. Define the pipeline steps as an ordered array:
   ```javascript
   const steps = [
     { name: 'parse-gpx', script: 'scripts/parse-gpx.js' },
     { name: 'resolve-annotations', script: 'scripts/resolve-annotations.js' },
   ];
   ```
4. For each step, log `[pipeline] Running ${name}...` to stdout, then run `execFileSync(process.execPath, [script], { cwd: projectRoot, stdio: 'inherit' })`. Using `process.execPath` ensures the same Node binary is used.
5. After all steps complete, log `[pipeline] Complete — all data files generated.`
6. Wrap in try/catch — on error, log `[pipeline] FAILED at ${name}` and `process.exit(1)` so npm lifecycle hooks abort the build.

Update `package.json` scripts:
```json
{
  "scripts": {
    "pipeline": "node scripts/pipeline.js",
    "prebuild": "node scripts/pipeline.js",
    "predev": "node scripts/pipeline.js",
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview"
  }
}
```

**IMPORTANT**: `prebuild` and `predev` are automatic npm lifecycle hooks — they run before `build` and `dev` respectively. The `pipeline` script is the same command as a convenience for manual invocation.

<task type="auto">
  <name>Task 2: Create Astro content config with Zod schemas</name>
  <files>src/content.config.ts</files>
  <action>
Create `src/content.config.ts` for Astro content collections using the `file()` loader:

```typescript
import { defineCollection, z } from 'astro:content';
import { file } from 'astro/loaders';
```

**Route data collection**: The `route-data.json` file is a single object (not an array of objects with id). Use the `file()` loader with a custom `parser` callback to wrap it as an array entry:

```typescript
const routeData = defineCollection({
  loader: file('public/data/route-data.json', {
    parser: (text) => {
      const data = JSON.parse(text);
      return [{ id: 'route', ...data }];
    },
  }),
  schema: z.object({
    id: z.string(),
    points: z.array(z.object({
      lat: z.number(),
      lon: z.number(),
      ele: z.number(),
      miles: z.number(),
    })),
    meta: z.object({
      totalMiles: z.number(),
      elevationGainMeters: z.number(),
      elevationGainFeet: z.number(),
      pointCount: z.number(),
      originalPointCount: z.number(),
      simplificationTolerance: z.number(),
      elevationThresholdMeters: z.number(),
    }),
  }),
});
```

**Annotations collection**: `annotations.json` is already an array of objects with `id` fields, so the default `file()` loader works directly:

```typescript
const annotations = defineCollection({
  loader: file('public/data/annotations.json'),
  schema: z.discriminatedUnion('type', [
    z.object({
      id: z.string(),
      type: z.literal('sector'),
      name: z.string(),
      startMile: z.number(),
      endMile: z.number(),
      lengthMiles: z.number(),
      startLat: z.number(),
      startLon: z.number(),
      endLat: z.number(),
      endLon: z.number(),
      startIdx: z.number(),
      endIdx: z.number(),
    }),
    z.object({
      id: z.string(),
      type: z.literal('restock'),
      name: z.string(),
      mile: z.number(),
      lat: z.number(),
      lon: z.number(),
      ele: z.number(),
      snapIdx: z.number(),
    }),
  ]),
});
```

**Photos collection** (stub for Phase 7): Define a placeholder schema that will be populated later when photos.json exists:

```typescript
const photos = defineCollection({
  loader: file('public/data/photos.json', {
    parser: (text) => {
      try { return JSON.parse(text); }
      catch { return []; }
    },
  }),
  schema: z.object({
    id: z.string(),
    filename: z.string(),
    thumb: z.string(),
    mile: z.number(),
    lat: z.number().optional(),
    lon: z.number().optional(),
  }),
});
```

Export all collections:
```typescript
export const collections = { routeData, annotations, photos };
```

**IMPORTANT**: The `file()` loader paths are relative to the project root. Since the pipeline runs before build, these files will exist when Astro processes them.

**NOTE on photos stub**: The photos loader uses a try/catch parser so the build doesn't fail when `photos.json` doesn't exist yet (Phase 7). This is a stub — the schema will be validated properly once photos.json is produced.
