  In `src/pages/index.astro`, the root cause is `.amber-section :global(span)` forcing `color: forest-900` on ALL spans inside the amber section — including `.stat-value` and `.stat-label` in RouteStats.astro which sit on `forest-800` card backgrounds (dark text on dark green = ~1.2:1 contrast ratio).

  Fix by adding targeted overrides AFTER the existing `.amber-section :global(span)` rule. Add these rules to the existing `<style>` block in `index.astro`:

  ```css
  /* VIS-05: Route stats legibility — override amber-section span color on stat cards */
  .amber-section :global(.stat-value) {
    color: var(--color-amber-500);
  }
  .amber-section :global(.stat-label) {
    color: var(--color-cream-200);
  }
  .amber-section :global(.surface-name) {
    color: var(--color-forest-950);
  }
  .amber-section :global(.surface-miles) {
    color: var(--color-forest-900);
  }
  ```

  This preserves the amber section's dark text intent for general content while restoring the stat card's original high-contrast colors (amber-500 value on forest-800 card = ~4.8:1, cream-200 label on forest-800 = ~5.2:1). The surface breakdown rows (.surface-name, .surface-miles) keep dark text since they sit directly on the amber-500 background without a card.

  Do NOT use `!important`. Do NOT move RouteStats out of the amber section. The cascade fix is cleaner.

<task type="auto">
  <name>Task 2: Add photo gallery skeleton loaders with shimmer animation</name>
  <files>src/styles/global.css, src/components/PhotoGallery.astro</files>
  <action>
  **1. Add shimmer keyframes to global.css (at the end of the `@layer base` block):**

  ```css
  /* PERF-01: Skeleton shimmer animation for image loading */
  @keyframes shimmer {
    0% { background-position: -200% 0; }
    100% { background-position: 200% 0; }
  }
  ```

  **2. Update PhotoGallery.astro — add width/height attributes and skeleton wrapper:**

  In the `<img>` element inside the `.map()`, add `width` and `height` attributes from `parseDims()` to prevent CLS. Wrap each `<img>` in a skeleton container that shows a shimmer animation until the image loads.

  Update the `<img>` tag to include dimensions:
  ```html
  <img
    src={photo.thumb}
    alt=""
    loading="lazy"
    decoding="async"
    width={dims.w}
    height={dims.h}
    class="w-full h-auto block"
  />
  ```

  Add the skeleton CSS class to each `<a>` wrapper. Add the class `img-skeleton` to the `<a>` element's class:list array. This makes the `<a>` show the shimmer background until its child image loads.

  **3. Add skeleton CSS in the `<style>` block of PhotoGallery.astro:**

  ```css
  .img-skeleton {
    background: linear-gradient(
      90deg,
      var(--color-forest-800) 25%,
      var(--color-forest-700) 50%,
      var(--color-forest-800) 75%
    );
    background-size: 200% 100%;
    animation: shimmer 1.5s ease-in-out infinite;
  }

  .img-skeleton.loaded {
    background: none;
    animation: none;
  }

  @media (prefers-reduced-motion: reduce) {
    .img-skeleton {
      animation: none;
      background: var(--color-forest-800);
    }
  }
  ```

  **4. Add JS load-event handler in the existing `<script>` block of PhotoGallery.astro:**

  BEFORE the PhotoSwipe lightbox initialization code, add image load detection:

  ```javascript
  // PERF-01: Remove skeleton shimmer once each image loads
  document.querySelectorAll('.img-skeleton').forEach(wrapper => {
    const img = wrapper.querySelector('img');
    if (!img) return;
    
    function markLoaded() {
      wrapper.classList.add('loaded');
    }
    
    if (img.complete) {
      markLoaded();
    } else {
      img.addEventListener('load', markLoaded, { once: true });
      img.addEventListener('error', markLoaded, { once: true }); // Remove shimmer even on error
    }
  });
  ```

  This handles both cached images (img.complete is already true) and images that load after script execution. The `{ once: true }` option auto-removes the listener.
