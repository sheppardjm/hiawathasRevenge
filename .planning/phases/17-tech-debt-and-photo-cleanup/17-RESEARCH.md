## Research Area 2: CSS Brace Imbalance in index.astro

### Finding

**File:** `src/pages/index.astro`
**Lines:** 81–111 (the `<style>` block)

The brace imbalance is at lines 105–110:

```css
@media (min-width: 640px) {        /* line 105 — opens, NEVER CLOSED */
@media (prefers-reduced-motion: reduce) {  /* line 106 */
  .gpx-download {
    transition: none;
  }
}                                  /* line 110 — closes prefers-reduced-motion */
```

The `@media (min-width: 640px)` block opens but has no matching closing brace. The `</style>` tag on line 111 closes the block implicitly in the browser, but the intent is wrong: the `prefers-reduced-motion` rule should apply at ALL viewport widths, not just `>=640px`.

**Current broken behavior:** Mobile users with `prefers-reduced-motion: reduce` still see the `0.2s transition` on `.gpx-download` because the media query is gated on `min-width: 640px`.

**Fix:** Remove the `@media (min-width: 640px) {` wrapper entirely. The corrected block:

```css
@media (prefers-reduced-motion: reduce) {
  .gpx-download {
    transition: none;
  }
}
```

This requires removing line 105 (`@media (min-width: 640px) {`) — the inner media query and its closing brace are already correctly formed.

**Confidence:** HIGH — direct file inspection, brace-counted manually.

## Research Area 3: gold-600 WCAG AA Comment

### Finding

**File:** `src/styles/global.css`
**Line 47:** `/* Gold family — PASSES AA normal text on forest-900 and forest-950 */`
**Lines 48–50:** `--color-gold-600`, `--color-gold-500`, `--color-gold-400`

**The inaccuracy:** The comment claims the entire gold family passes AA normal text. But gold-600 (`#b8860b`) measures 4.45:1 contrast against forest-900 (`#1a2e1a`) — 0.05 below the WCAG 4.5:1 threshold for AA normal text. It passes AA large text (3:1 threshold) only.

**Current usage of gold-600:** Zero. Grep of `gold-600` in `src/` returns only the variable definition. No component uses it.

**gold-500 and gold-400 status:** These are brighter/lighter and have higher contrast ratios. The claim "PASSES AA normal text" applies to gold-500 and gold-400, not gold-600.

**Fix:** Rewrite the comment to accurately describe gold-600's actual WCAG status:

```css
/* Gold family — gold-600 passes AA large text only (4.45:1); gold-500/400 pass AA normal text */
```

**Confidence:** HIGH — contrast ratio from v1.1 audit is authoritative (4.45:1 stated in audit), usage confirmed by grep.

## Research Area 5: Build Pipeline

### How it works

```
npm run build
  → prebuild hook → node scripts/pipeline.js
    1. parse-gpx.js         → public/data/route-data.json
    2. resolve-annotations.js → public/data/annotations.json
    3. generate-thumbnails.js → public/thumbs/*.webp  (reads images/, DOES NOT delete old files)
    4. copy-images.js        → public/images/*.jpg    (reads images/, DOES NOT delete old files)
    5. match-photos.js       → public/data/photos.json (rewrites from scratch each run)
    6. copy-gpx.js           → public/*.gpx
  → astro build             → dist/ (gitignored)
```

### Critical pipeline behavior

- **generate-thumbnails.js** does NOT delete stale thumbails. It only creates/overwrites files for whatever is currently in `images/`. If you delete files from `images/` but don't delete the corresponding `public/thumbs/` files, those stale thumbnails will remain.
- **copy-images.js** does NOT delete stale public images. Same pattern.
- **match-photos.js** DOES completely rewrite `photos.json` from scratch. No stale cleanup needed there.

### Correct cleanup order

1. Remove 3 `(1)` entries from `public/data/photos-manifest.json`
2. Delete 3 `(1).jpg` files from `images/` (source)
3. Delete 3 `(1).jpg` files from `public/images/` (public copy — optional since pipeline doesn't delete, but needed for correctness)
4. Delete 3 `_(1).webp` files from `public/thumbs/` (thumbnails — same)
5. Run `npm run pipeline` to regenerate `photos.json` (will produce 51 entries)
6. Run `npm run build` to verify full build passes

**Confidence:** HIGH — pipeline scripts read directly, behavior verified.

## Common Pitfalls

### Pitfall 1: Forgetting the comment line above .topo-divider
**What goes wrong:** Line 180 (`/* Topographic contour divider ... */`) is left behind as orphaned comment with no rule below it.
**Fix:** Delete both the comment (line 180) and the rule (lines 181–187) together.

### Pitfall 2: Thumbnail naming difference
**What goes wrong:** Trying to delete `bhrt78....(1).webp` (with space) but the actual thumbnail file is `bhrt78...._(1).webp` (with underscore).
**Why it happens:** `generate-thumbnails.js` replaces all spaces with underscores in the output filename.
**How to avoid:** Delete using the `_(1).webp` pattern for thumbnails.

### Pitfall 3: Leaving public/images and public/thumbs stale
**What goes wrong:** Deleting from `images/` and `photos-manifest.json`, but forgetting `public/images/` and `public/thumbs/`. The pipeline does not clean these on rerun.
**Fix:** Delete all three file locations explicitly before running pipeline.

### Pitfall 4: gold-600 comment scope
**What goes wrong:** The comment on line 47 covers the entire gold family block (lines 48–50). Rewording must accurately distinguish gold-600 from gold-500/400.
**Fix:** The new comment should call out gold-600 specifically as large-text-only, while confirming gold-500/400 pass AA normal text.

### Pitfall 5: Brace fix introduces wrong structure
**What goes wrong:** Adding a closing `}` to close the `@media (min-width: 640px)` instead of removing the wrapper.
**Why it's wrong:** The goal is `prefers-reduced-motion` at ALL widths, not just `>=640px`. Adding a close brace would keep the viewport restriction.
**Fix:** Remove line 105 (`@media (min-width: 640px) {`). The inner `@media (prefers-reduced-motion: reduce)` is already properly formed.
