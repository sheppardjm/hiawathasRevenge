The `onHover` callback in Chart.js 4.5.1 options is not reliably firing. This is a known issue with Chart.js 4.x when using `parsing: false` and certain configurations — the internal event system may not trigger onHover consistently.

**Fix approach:** Replace the `onHover` callback in chart options with a direct `canvas.addEventListener('mousemove', ...)` listener after chart creation. This bypasses Chart.js event system entirely and is more reliable.

Step 1: **Remove the `onHover` callback** from the chart options object (lines 88-101). Delete the entire onHover property.

Step 2: **Add a canvas mousemove listener** after the chart is created (after line 151, before the existing mouseleave listener at line 154). Add:

```javascript
// Direct canvas mousemove — bypasses Chart.js onHover which is unreliable with parsing:false in v4.5.1
canvas.addEventListener('mousemove', (e) => {
  const rect = canvas.getBoundingClientRect();
  const pos = {
    x: e.clientX - rect.left,
    y: e.clientY - rect.top
  };
  const miles = chart.scales.x.getValueForPixel(pos.x);
  if (miles == null) return;
  // Clamp to valid range
  const clamped = Math.max(0, Math.min(data[data.length - 1].x, miles));
  // Dispatch CustomEvent for RouteMap crosshair sync
  window.dispatchEvent(new CustomEvent('elevation:hover', { detail: { miles: clamped } }));
  // Update crosshair line position
  chart.options.plugins.annotation.annotations.crosshair.xMin = clamped;
  chart.options.plugins.annotation.annotations.crosshair.xMax = clamped;
  chart.options.plugins.annotation.annotations.crosshair.display = true;
  chart.update('none');
});
```

Step 3: Verify the existing `mouseleave` listener (line 154) still works — it already uses `canvas.addEventListener('mouseleave', ...)` which is the same pattern.

**Important:** Keep the `events` array in chart options as default (do NOT add `events: []` to suppress Chart.js events — the tooltip still needs mousemove to function). The chart tooltip config (mode: 'index', intersect: false) should continue to work since Chart.js still processes its own events for tooltips.

Actually, there is a subtlety: with both Chart.js internal event handling AND our canvas mousemove listener, the tooltip AND crosshair will both work. Chart.js tooltip uses its own internal event pipeline; our crosshair uses the direct DOM listener. This is the correct separation.
