# Phase 7: Photo Pipeline - Research

**Researched:** 2026-03-31
**Domain:** Node.js image processing (sharp), build pipeline scripting, JSON data generation
**Confidence:** HIGH

## Summary

This phase has two distinct scripts: `generate-thumbnails.js` (batch WebP conversion with sharp) and `match-photos.js` (manifest-driven JSON generation snapping mileage to route coordinates). Both follow patterns already established in the codebase (`pipeline.js` orchestrator, `resolve-annotations.js` snapByMileage pattern, `parse-gpx.js` file I/O pattern).

sharp 0.34.5 is the current release and is fully compatible with Node 25 (`>=21.0.0` satisfies its `>=21.0.0` engine requirement). The sharp API is straightforward: `.autoOrient()` corrects EXIF rotation before resize, `.resize({ width: 400 })` preserves aspect ratio (height is auto-calculated), `.webp({ quality: 80 })` produces the required format, and `.toFile(path)` writes to disk returning a Promise. Batch processing 54 JPEGs sequentially is fine for a build script — no concurrency overhead needed.

The photos.json format is already defined in `src/content.config.ts`: array of `{ id, filename, thumb, mile, lat?, lon? }`. The match-photos script reads a `photos-manifest.json` (written by Phase 9 admin UI), validates that each entry's filename exists on disk, snaps the mileage to route coordinates using the identical `snapByMileage` pattern from `resolve-annotations.js`, and writes `public/data/photos.json`.

**Primary recommendation:** Install `sharp` as a devDependency, implement both scripts as plain ESM Node modules following the exact file-I/O pattern used by `parse-gpx.js` and `resolve-annotations.js`, add them to the `steps` array in `pipeline.js`, and handle the absent `photos-manifest.json` gracefully (write empty `photos.json` array, log a warning — matching the existing try/catch empty-array pattern in `content.config.ts`).

### Pattern 1: Sharp Thumbnail Generation (ESM, pipeline-compatible)
**What:** Read source JPEGs, auto-orient, resize to 400px wide, output WebP at 80% quality.
**When to use:** Whenever source images need thumbnail generation at build time.

```javascript
// Source: https://sharp.pixelplumbing.com/api-output#webp
// Source: https://sharp.pixelplumbing.com/api-resize
// Source: https://sharp.pixelplumbing.com/api-operation#rotate
import sharp from 'sharp';
import { readdirSync, mkdirSync, existsSync } from 'fs';
import { join, extname, basename } from 'path';
import { fileURLToPath } from 'url';
import { dirname } from 'path';

const __dirname = dirname(fileURLToPath(import.meta.url));
const ROOT = join(__dirname, '..');

const SRC_DIR = join(ROOT, 'images');
const OUT_DIR = join(ROOT, 'public', 'thumbs');

mkdirSync(OUT_DIR, { recursive: true });

const jpgFiles = readdirSync(SRC_DIR).filter(
  (f) => extname(f).toLowerCase() === '.jpg'
);

for (const filename of jpgFiles) {
  const srcPath = join(SRC_DIR, filename);
  // Derive output name: replace spaces with underscores, swap extension
  const thumbName = basename(filename, extname(filename)).replace(/ /g, '_') + '.webp';
  const outPath = join(OUT_DIR, thumbName);

  await sharp(srcPath)
    .autoOrient()                    // corrects EXIF rotation, removes EXIF tag
    .resize({ width: 400 })         // preserves aspect ratio; height auto-calculated
    .webp({ quality: 80 })
    .toFile(outPath);
}
```

Key points:
- `autoOrient()` is the correct method in sharp 0.34.x (introduced as dedicated API; previously `rotate()` without args)
- `resize({ width: 400 })` with only width specified auto-calculates height to preserve aspect ratio (no `fit` needed for width-only resize)
- Sequential `await` in `for...of` loop is appropriate for a build script; no concurrency throttling needed for 54 images
- `mkdirSync(OUT_DIR, { recursive: true })` matches parse-gpx.js pattern

### Pattern 2: Match Photos Script (mileage snapping, graceful absent-manifest)
**What:** Read photos-manifest.json, validate entries, snap mileage to route coords, write photos.json.
**When to use:** Build time, after GPX parse step (route-data.json must exist).

```javascript
// Source: resolve-annotations.js in this project (snapByMileage pattern)
import { readFileSync, writeFileSync, existsSync } from 'fs';
import { resolve } from 'path';
import { fileURLToPath } from 'url';
import { dirname } from 'path';

const __dirname = dirname(fileURLToPath(import.meta.url));
const ROOT = resolve(__dirname, '..');

const MANIFEST_PATH = resolve(ROOT, 'public', 'data', 'photos-manifest.json');
const ROUTE_PATH = resolve(ROOT, 'public', 'data', 'route-data.json');
const OUTPUT_PATH = resolve(ROOT, 'public', 'data', 'photos.json');

// Graceful absent manifest — matches content.config.ts try/catch pattern
if (!existsSync(MANIFEST_PATH)) {
  console.warn('match-photos: photos-manifest.json not found — writing empty photos.json');
  writeFileSync(OUTPUT_PATH, '[]', 'utf8');
  process.exit(0);
}

const manifest = JSON.parse(readFileSync(MANIFEST_PATH, 'utf8'));
const routeData = JSON.parse(readFileSync(ROUTE_PATH, 'utf8'));
const routePoints = routeData.points;

function snapByMileage(targetMile, points) {
  // identical to resolve-annotations.js implementation
  let bestIdx = 0;
  let bestDiff = Infinity;
  for (let i = 0; i < points.length; i++) {
    const diff = Math.abs(points[i].miles - targetMile);
    if (diff < bestDiff) { bestDiff = diff; bestIdx = i; }
  }
  const pt = points[bestIdx];
  return { lat: pt.lat, lon: pt.lon, miles: pt.miles };
}

const photos = manifest.map((entry) => {
  const snap = snapByMileage(entry.mile, routePoints);
  return {
    id: entry.filename,          // unique id required by Astro content collection
    filename: entry.filename,
    thumb: `/thumbs/${entry.thumbname}`,
    mile: snap.miles,
    lat: snap.lat,
    lon: snap.lon,
  };
});

writeFileSync(OUTPUT_PATH, JSON.stringify(photos, null, 2), 'utf8');
```

### Pattern 4: Thumbnail Filename Derivation
**What:** Map source filename to thumbnail filename in a reproducible, URL-safe way.
**Challenge:** Source filenames contain spaces (3 files: `bhrt78...1536x2048 (1).jpg`), parentheses, and underscores. These need to map to the `thumb` path stored in photos.json.

Recommended approach: Replace spaces with underscores, drop parentheses-and-number suffixes (treating `(1)` duplicates as distinct files by keeping the space-replaced name):

```javascript
// Simple, reversible: replace spaces with '_'
const thumbName = basename(filename, '.jpg').replace(/ /g, '_') + '.webp';
// "bhrt78...1536x2048 (1).jpg" -> "bhrt78...1536x2048_(1).webp"
```

The `thumb` field in photos.json stores the URL path: `/thumbs/bhrt78...1536x2048_(1).webp`. The match-photos script must use the same derivation to construct `thumb` values.

### Pattern 5: Lazy-Load HTML Attributes (PHOTO-06)
**What:** Gallery `<img>` elements require `loading="lazy"` and `decoding="async"`.
**Where applied:** In Astro component rendering, not in the pipeline scripts. The pipeline scripts only produce photos.json and thumbnail files. The HTML attributes are applied when rendering the gallery in a later phase.

### Anti-Patterns to Avoid
- **Running sharp synchronously:** sharp's `.toFile()` returns a Promise; always `await` it. The pipeline script must use top-level `await` (valid in ESM modules) or wrap in an async IIFE.
- **Using `rotate()` instead of `autoOrient()`:** In sharp 0.34.x, use `.autoOrient()` explicitly. The parameter-less `rotate()` still works (calls `autoOrient()` for backwards compatibility) but is less expressive.
- **Storing thumbnails in `src/` or `images/`:** Thumbnails must go in `public/thumbs/` so Astro serves them as static assets at `/thumbs/filename.webp`.
- **Hardcoding photo-to-mileage mapping in scripts:** The manifest JSON pattern keeps mileage data out of the script and editable by the Phase 9 admin UI.
- **Not creating output directories:** `public/thumbs/` does not exist yet; `mkdirSync(OUT_DIR, { recursive: true })` must precede any writes.
- **Using ESM top-level await without `"type": "module"`:** The project already has `"type": "module"` in package.json, so top-level await is valid in `.js` scripts.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JPEG decoding, WebP encoding | Custom encoder/decoder | `sharp` | Handles all EXIF quirks, color profiles, orientation, progressive JPEG; battle-tested |
| EXIF orientation correction | Read EXIF tags manually, rotate pixel data | `sharp.autoOrient()` | EXIF orientation has 8 possible values including mirrored variants; getting it right manually is error-prone |
| Aspect-ratio-preserving resize | Calculate target height manually | `sharp.resize({ width: 400 })` | Passing only `width` auto-calculates height with correct rounding |
| Thumbnail filename → URL path mapping | Regex/encoding library | Plain `string.replace(/ /g, '_')` | The filenames contain spaces but no other problematic URL characters; simple replacement is sufficient |
| Mileage snapping | Custom nearest-neighbor search | Existing `snapByMileage` from `resolve-annotations.js` | Already proven, handles edge cases, consistent with all other annotations |

**Key insight:** This phase is entirely buildable with sharp + the existing pipeline patterns. No new architectural primitives are needed.

## Common Pitfalls

### Pitfall 1: Images processed top-level with no async context
**What goes wrong:** `sharp(path).toFile(out)` returns a Promise. If the script is written synchronously (no await/async), the promises are silently abandoned, no files are written, and the script exits 0.
**Why it happens:** Pipeline scripts look synchronous (parse-gpx.js uses `readFileSync`/`writeFileSync`), so it's natural to write generate-thumbnails the same way. But sharp has no sync API.
**How to avoid:** Either use top-level `await` (valid since ESM + Node 18+) or wrap in an `async` IIFE. The `for...of` + `await sharp(...).toFile()` pattern is cleanest.
**Warning signs:** Script reports "complete" instantly; `public/thumbs/` contains 0 files.

### Pitfall 2: EXIF rotation ignored — portrait images appear landscape
**What goes wrong:** Phone camera images stored at 1536x2048 contain EXIF Orientation tag indicating the physical rotation. Without `.autoOrient()`, sharp uses raw pixel dimensions and the output thumbnail appears rotated 90 degrees.
**Why it happens:** sharp does not auto-apply EXIF orientation by default.
**How to avoid:** Always call `.autoOrient()` before `.resize()` in the chain.
**Warning signs:** Thumbnail of a portrait photo appears landscape (wide) in the browser.

### Pitfall 3: Duplicate filename collision in `public/thumbs/`
**What goes wrong:** Source images include 3 `(1)` duplicates: `bhrt78...1536x2048 (1).jpg` alongside `bhrt78...1536x2048.jpg`. The generate-thumbnails script must not silently overwrite or skip either file.
**Why it happens:** The space+parenthesis pattern is a macOS/Finder download duplication artifact.
**How to avoid:** The replacement `replace(/ /g, '_')` preserves the `(1)` in the output filename (`...1536x2048_(1).webp`), so both source files produce distinct thumbnail files. Verify the thumb count matches the source count.
**Warning signs:** 54 source JPEGs but only 51 WebP thumbnails in `public/thumbs/`.

### Pitfall 4: photos-manifest.json absent causes pipeline failure
**What goes wrong:** If match-photos.js tries to `readFileSync('photos-manifest.json')` and the file doesn't exist (Phase 9 hasn't run yet), the pipeline throws and `npm run build` fails.
**Why it happens:** Phase 9 (admin UI) hasn't been built yet during Phase 7 development.
**How to avoid:** Use `existsSync` check — if manifest absent, write `[]` to photos.json and exit 0. This matches the `try { return JSON.parse(text); } catch { return []; }` pattern already in `content.config.ts`.
**Warning signs:** `npm run pipeline` fails with ENOENT on photos-manifest.json.

### Pitfall 5: `thumb` path format inconsistency between generate-thumbnails and match-photos
**What goes wrong:** generate-thumbnails writes `public/thumbs/foo_bar.webp` but match-photos stores `thumb: 'thumbs/foo_bar.webp'` (missing leading `/`). The browser requests `/thumbs/foo_bar.webp` which is correct, but the Astro content collection validation may reject the path format.
**Why it happens:** URL paths vs. filesystem paths conflated in different scripts.
**How to avoid:** match-photos always stores thumb as an absolute URL path: `/thumbs/{thumbname}`. The filename derivation logic is defined once (in generate-thumbnails.js) and match-photos uses the identical derivation.
**Warning signs:** Photos load in some contexts but return 404 in others; Astro schema validation errors at build.

### Pitfall 6: sharp excluded from Astro/Vite bundling
**What goes wrong:** Vite may try to bundle sharp, which contains native `.node` binaries, causing the build to fail.
**Why it happens:** sharp explicitly cannot be bundled.
**How to avoid:** sharp is only used in build scripts (`scripts/`), never imported in Astro pages or components. The pipeline runs via `execFileSync(process.execPath, [script])` — completely outside Vite's module graph. No Vite exclusion config needed for this use pattern.
**Warning signs:** Only a concern if sharp is imported in `src/` files.

### Complete generate-thumbnails.js (production pattern)
```javascript
// Source: https://sharp.pixelplumbing.com/api-output#webp
// Source: https://sharp.pixelplumbing.com/api-resize
// Source: https://sharp.pixelplumbing.com/api-operation#rotate (autoOrient)
import sharp from 'sharp';
import { readdirSync, mkdirSync } from 'fs';
import { join, extname, basename, dirname } from 'path';
import { fileURLToPath } from 'url';

const __dirname = dirname(fileURLToPath(import.meta.url));
const ROOT = join(__dirname, '..');
const SRC_DIR = join(ROOT, 'images');
const OUT_DIR = join(ROOT, 'public', 'thumbs');

mkdirSync(OUT_DIR, { recursive: true });

const sourceFiles = readdirSync(SRC_DIR).filter(
  (f) => extname(f).toLowerCase() === '.jpg'
);

let generated = 0;
for (const filename of sourceFiles) {
  const srcPath = join(SRC_DIR, filename);
  const thumbName = basename(filename, extname(filename)).replace(/ /g, '_') + '.webp';
  const outPath = join(OUT_DIR, thumbName);

  const info = await sharp(srcPath)
    .autoOrient()
    .resize({ width: 400 })
    .webp({ quality: 80 })
    .toFile(outPath);

  generated++;
  console.log(`  ${thumbName} (${info.width}x${info.height}, ${info.size} bytes)`);
}

console.log(`generate-thumbnails: complete`);
console.log(`  Source images : ${sourceFiles.length}`);
console.log(`  Thumbnails    : ${generated}`);
console.log(`  Output        : public/thumbs/`);
```

## Open Questions

1. **Thumbnail filename for match-photos input**
   - What we know: generate-thumbnails derives `thumbName` by replacing spaces with `_`. match-photos needs to reference the same name in the `thumb` field.
   - What's unclear: Should photos-manifest.json include the `thumbname` field explicitly (so admin UI controls it), or should match-photos derive it from `filename` using the same algorithm?
   - Recommendation: Have match-photos derive the thumbname from filename using the same `replace(/ /g, '_')` + `.webp` logic. This keeps photos-manifest.json minimal (only `filename` + `mile`) and avoids duplicating derivable data.

2. **Handling photos-manifest.json before Phase 9**
   - What we know: photos-manifest.json won't exist until Phase 9.
   - What's unclear: Should match-photos create an empty `photos.json` (so the collection loads []) or skip writing it entirely?
   - Recommendation: Write `[]` to photos.json when manifest is absent. This matches the `content.config.ts` fallback behavior and prevents the Astro [ERROR] from the file-loader trying to parse a missing file.

3. **`inspiration/` subdirectory in images/**
   - What we know: `images/inspiration/` exists with WebP files — these are reference/inspiration images, not route photos.
   - What's unclear: Should generate-thumbnails process only top-level `.jpg` files, or also recurse into subdirectories?
   - Recommendation: Use `readdirSync(SRC_DIR).filter(f => extname(f).toLowerCase() === '.jpg')` which returns only top-level files (not subdirectory entries). This naturally excludes `inspiration/` without special-casing it.
