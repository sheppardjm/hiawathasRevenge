<task type="auto">
  <name>Task 1: Create match-photos.js</name>
  <files>scripts/match-photos.js</files>
  <action>
    Create `scripts/match-photos.js` as an ESM module following the resolve-annotations.js file-I/O pattern.

    Structure:
    1. Imports: readFileSync, writeFileSync, existsSync from 'fs'; resolve, dirname from 'path'; fileURLToPath from 'url'.
    2. Derive `__dirname` and `ROOT` using the same pattern as resolve-annotations.js.
    3. Define paths:
       - `MANIFEST_PATH = resolve(ROOT, 'public', 'data', 'photos-manifest.json')`
       - `ROUTE_PATH = resolve(ROOT, 'public', 'data', 'route-data.json')`
       - `OUTPUT_PATH = resolve(ROOT, 'public', 'data', 'photos.json')`
    4. Graceful absent-manifest check — if photos-manifest.json does not exist:
       - `console.warn('match-photos: photos-manifest.json not found — writing empty photos.json');`
       - `writeFileSync(OUTPUT_PATH, '[]', 'utf8');`
       - `process.exit(0);`
       This matches the try/catch empty-array pattern in content.config.ts.
    5. If manifest exists, parse it and load route-data.json:
       - `const manifest = JSON.parse(readFileSync(MANIFEST_PATH, 'utf8'));`
       - `const routeData = JSON.parse(readFileSync(ROUTE_PATH, 'utf8'));`
       - `const routePoints = routeData.points;`
    6. Implement `snapByMileage(targetMile, points)` — copy from resolve-annotations.js exactly:
       - Linear scan over points[i].miles
       - Track bestIdx/bestDiff
       - Return `{ lat: round(pt.lat, 5), lon: round(pt.lon, 5), miles: round(pt.miles, 2) }`
       - Include the `round(value, decimals)` helper from resolve-annotations.js
    7. Map manifest entries to photos.json format:
       ```
       const photos = manifest.map((entry) => {
         const snap = snapByMileage(entry.mile, routePoints);
         const thumbName = basename(entry.filename, extname(entry.filename)).replace(/ /g, '_') + '.webp';
         return {
           id: entry.filename,
           filename: entry.filename,
           thumb: `/thumbs/${thumbName}`,
           mile: snap.miles,
           lat: snap.lat,
           lon: snap.lon,
         };
       });
       ```
       Note: Import basename and extname from 'path' for the thumb derivation.
       CRITICAL: The thumb filename derivation (`replace(/ /g, '_') + '.webp'`) MUST be identical to the logic in generate-thumbnails.js. This ensures the `thumb` URL in photos.json points to the actual file in public/thumbs/.
    8. Write output: `writeFileSync(OUTPUT_PATH, JSON.stringify(photos, null, 2), 'utf8');`
    9. Log summary: entry count, output path.

    Output schema MUST match content.config.ts photos collection:
    - `id`: string (use filename)
    - `filename`: string
    - `thumb`: string (absolute URL path like `/thumbs/foo.webp`)
    - `mile`: number
    - `lat`: number (optional in schema but always present from snapByMileage)
    - `lon`: number (optional in schema but always present from snapByMileage)

    Add JSDoc comment block:
    ```
    /**
     * match-photos.js
     *
     * Reads photos-manifest.json, validates entries, snaps mileage values
     * to route coordinates, and writes public/data/photos.json.
     * If photos-manifest.json is absent, writes an empty array.
     *
     * Usage: node scripts/match-photos.js
     */
    ```
