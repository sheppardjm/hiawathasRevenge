    **Step 2 — Add `<video>` element to HeroSection.astro:**

    Insert a `<video>` element immediately AFTER the closing `</picture>` tag (line ~29) and BEFORE the `<div class="hero-overlay">` (line ~30). The video sits in the same layer stack as the image — both absolutely positioned with `inset: 0`. The video renders on top of the image (later in DOM order), so when video plays it covers the image; when video fails, the image shows through.

    ```html
    <video
      class="hero-video"
      autoplay
      muted
      loop
      playsinline
      poster="/images/irrVhAXHnnFzslJGVemLiPEy5iQFbqZF6VzqxYOHL1o-2048x1536.jpg"
    >
      <source src="/Stationary_Hero_Video_With_Motion.mp4" type="video/mp4" />
    </video>
    ```

    Key attributes:
    - `autoplay` + `muted`: Required together — browsers block autoplay of unmuted video
    - `loop`: Continuous playback
    - `playsinline`: Prevents iOS Safari from going fullscreen
    - `poster`: Uses the existing hero JPG as the poster frame (shown before video loads)
    - No `preload` attribute needed — `autoplay` implies the browser will load it

    **Step 3 — Add `.hero-video` CSS:**

    Add the following CSS inside the existing `<style>` block, after the `.hero-img` rule (after line ~89):

    ```css
    .hero-video {
      position: absolute;
      inset: 0;
      width: 100%;
      height: 100%;
      object-fit: cover;
      object-position: center;
      z-index: 0;
    }
    ```

    The z-index: 0 keeps the video behind the overlay (which has no z-index but comes later in stacking context) and behind hero-content (z-index: 1). The image has no z-index, so the video (z-index: 0) will render on top of it by DOM order since both are absolutely positioned.

    Also add a reduced-motion rule inside the existing `@media (prefers-reduced-motion: reduce)` block if one exists, or as a new media query if not. Since HeroSection.astro does NOT currently have a reduced-motion media query, add one:

    ```css
    @media (prefers-reduced-motion: reduce) {
      .hero-video {
        display: none;
      }
    }
    ```

    Using `display: none` instead of JS pause because:
    - CSS-only solution, no JS dependency
    - Prevents the browser from downloading the video at all when reduced motion is preferred
    - The poster/image shows through naturally

    **Step 4 — Add reduced-motion JS for dynamic changes:**

    Add a `<script>` block at the end of HeroSection.astro (after the `</style>` tag). This handles the case where a user toggles reduced-motion preference while the page is loaded:

    ```html
    <script>
      const heroVideo = document.querySelector('.hero-video');
      if (heroVideo) {
        const mq = window.matchMedia('(prefers-reduced-motion: reduce)');
        if (mq.matches) {
          heroVideo.pause();
        }
        mq.addEventListener('change', () => {
          if (mq.matches) {
            heroVideo.pause();
            heroVideo.style.display = 'none';
          } else {
            heroVideo.style.display = '';
            heroVideo.play().catch(() => {});
          }
        });
      }
    </script>
    ```

    The `.catch(() => {})` on play() prevents unhandled promise rejection if the browser refuses autoplay.

    Do NOT:
    - Remove the existing `<picture><img>` — it remains as the fallback
    - Add the video to Astro's asset pipeline (import) — large files go in public/
    - Add `controls` attribute — this is a background video, not a player
    - Omit `muted` — autoplay without muted is blocked everywhere
