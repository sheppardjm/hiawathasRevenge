    1. Add `id="gpx-download-link"` to the existing `<a>` element on line ~48 that currently has `href="/Munising_Hiawatha_s_Revenge.gpx"`. Keep the existing static href as the default (100mi is the default route).

    2. Add an inline `<script>` block at the end of `index.astro` (before the closing `</style>` tag is fine, or after it — follow Astro convention of script after style). The script must:

       a. Cache the routes manifest to avoid repeated fetches:
          ```javascript
          let _routesCache = null;
          async function getRoutes() {
            if (!_routesCache) _routesCache = await fetch('/data/routes.json').then(r => r.json());
            return _routesCache;
          }
          ```

       b. Listen for `route:change` on `window`:
          ```javascript
          window.addEventListener('route:change', async (e) => {
            const data = await getRoutes();
            const route = data.routes.find(r => r.id === e.detail.routeId);
            if (!route) return;
            const link = document.getElementById('gpx-download-link');
            if (!link) return;
            link.href = '/' + route.gpxFile;
            link.download = 'HiawathasRevenge-' + route.shortName + '.gpx';
            link.textContent = 'Download ' + route.name + ' GPX';
          });
          ```

    3. The static default remains `href="/Munising_Hiawatha_s_Revenge.gpx"` with text "Download GPX File" and `download="HiawathasRevenge.gpx"`. This is correct because `route:change` does NOT fire on initial page load — the map lazy-inits on scroll. The download section is far below the hero, so by the time a user reaches it after a route switch, the event will have fired.

    Do NOT modify the `.gpx-download` CSS class — it stays as-is.
