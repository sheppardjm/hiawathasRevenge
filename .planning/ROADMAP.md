## v1.6: Segment Editorial & Polish

**Goal:** Replace over-long segment descriptions with precise 35-55 word ecological blurbs, and ship three targeted UI/config fixes that have been deferred since v1.4.

**Coverage:** 6/6 v1.6 requirements mapped.

---

### Phase 38: UI & Config Quick Fixes

**Goal:** Visitors reading the map and opening the site see correctly-sized sector labels and a properly configured canonical URL; the 520 segment either has a hero photo or the gradient fallback is formally accepted as the shipped state.

**Dependencies:** None. All three fixes are independent single-file edits with no shared risk surface.

**Requirements:** LABEL-01, PHOTO-01, DEPLOY-01

**Success Criteria:**

1. Sector pill labels on the map display full segment names without truncation at zoom level 12 and above, with padding that does not clip the text.
2. The 520 segment card in the RouteExplorer shows either a hero photo sourced from CR-520 / Munising Falls (mile 0-5.0) or the gradient fallback is explicitly recorded as the accepted shipped state — no unresolved TODO exists for this segment.
3. `astro.config.ts` has `site` set to `https://hiawathasrevenge.com` with the `// TODO` comment removed; the build produces correct canonical URL meta tags.

---

### Phase 39: Segment Description Rewrite

**Goal:** Each of the 7 segment descriptions delivers precise ecological and surface character in 35-55 words, with the "Surface:" label pattern gone and the text consistent across every location that renders it.

**Dependencies:** Phase 38 complete (not a hard dependency — descriptions are independent of label/photo/URL fixes, but phase 38 clears the board so phase 39 can be the final commit of the milestone).

**Requirements:** DESC-01, DESC-02, DESC-03

**Success Criteria:**

1. Every segment description in the RouteExplainer reads as 35-55 words with a surface-first clause, an ecology clause grounded in observable species (sugar maple, jack pine, sweetfern, etc.), and no "Surface:" label.
2. The text shown in the map sector panel (from `sector-details.json`) is word-for-word identical to the text in `RouteExplainer.astro` for every segment — no silent divergence between the two rendering locations.
3. `sector-details.json` is up to date (regenerated by `generate-sector-details.js` after edits) and committed in the same changeset as the source files.
4. The `surface` field in `generate-sector-details.js` for each segment is consistent with the surface characterization in the rewritten description — no on-screen contradiction between the panel label and the blurb text.
