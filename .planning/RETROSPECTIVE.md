# Project Retrospective

*A living document updated after each milestone. Lessons feed forward into future planning.*

## Milestone: v1.11 — SEO & Social Sharing

**Shipped:** 2026-05-29
**Phases:** 4 (50-53) | **Plans:** 4 | **Tasks:** 8

### What Was Built
- Complete OpenGraph + Twitter Card meta set and Google-eligible Event JSON-LD (street address, timezone-aware startDate, free-event offers, geo) in BaseLayout.astro
- Shield-badge favicon across all targets (favicon.svg, 180x180 apple-touch-icon.png, 32x32 favicon.ico), generated by the build pipeline
- Branded 1200x630 og-card.jpg share image (badge + tagline + event date over dimmed hero) with a cache-busting filename
- robots.txt + @astrojs/sitemap crawlability, excluding /admin and /api/ and referencing sitemap-index.xml

### What Worked
- Tight, single-plan phases (1 plan each) executed cleanly — every phase summary reports "plan executed exactly as written," no deviations
- Front-loading the highest-SEO-impact template edits (Phase 50 meta/schema) and back-loading the lowest-priority crawlability work (Phase 53) matched effort to impact
- Reusing the phase 51 "inline SVG fill attributes for sharp/librsvg" lesson directly in phase 52 avoided re-discovering the same rasterization pitfall
- All asset generation (favicons, og-card) wired into the existing pipeline sharedSteps, so the artifacts self-heal on every build rather than being committed by hand

### What Was Inefficient
- The milestone shipped functionally on 2026-04-10 but wasn't formally closed until 2026-05-29 — a ~7-week gap where STATE/ROADMAP showed "complete" but the milestone was never archived
- No v1.11 milestone audit was run before close (skipped at close time), so requirement coverage rested on the traceability table rather than an independent check
- Phase 52 verification remained `human_needed` and Phase 53 UAT had 3 pending scenarios at close — verification/UAT lagged behind implementation and were deferred rather than resolved
- A backlog of older verification/debug artifacts (14 total) accumulated across v1.0–v1.11 without being cleared at earlier milestone closes

### Patterns Established
- **Pipeline-generated SEO assets:** font embedding via base64 @font-face data URIs in SVG (`scripts/fonts/`), sharp composite order resize → extract → composite → jpeg, inline fill attributes throughout
- **Cache-busting by filename** for social share images (og-card.jpg) rather than query strings
- **Sitemap filter pattern:** `@astrojs/sitemap` filter callback excluding build-time page files (/admin) that only redirect at runtime

### Key Lessons
1. sharp/librsvg does not reliably process `<style>` blocks — always use inline `fill`/`stroke` attributes on SVG passed to sharp for rasterization.
2. Schema.org type fidelity matters for Google rich results: `price` is string `"0"`, `isAccessibleForFree` is boolean `true`, and `og:locale` uses underscore `en_US`.
3. `@astrojs/sitemap` emits `sitemap-index.xml` as the entry point — robots.txt must reference that, not `sitemap.xml`, or Search Console 404s.
4. Close milestones promptly after the work lands; a long gap between "functionally done" and "archived" lets verification/UAT debt and stale STATE drift accumulate.

### Cost Observations
- Model mix: not instrumented this milestone
- Sessions: implementation across ~1 day (2026-04-09 → 2026-04-10); archived 2026-05-29
- Notable: phases were small and fast (1–2 min execution each per summaries); the cost center was research/planning per phase, not execution
