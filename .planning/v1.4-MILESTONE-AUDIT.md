## Critical Gaps

### 1. DEBT-02 Regression: NF2217-2218 Naming Reverts on Pipeline Run

**Severity:** Critical — user-visible inconsistency
**Location:** `scripts/resolve-annotations.js` line 28

The Phase 28 fix (commit `ce4523f`) correctly updated `annotations.json`, `sector-details.json`, and `sector-elevations.json` to use `"NF2217-2218"`. However, the fix was applied to the generated output files only. The source script `resolve-annotations.js` still hardcodes `name: 'NF2217'` on line 28. When the build pipeline runs (`npm run pipeline`), it regenerates these files from the source scripts, reverting the name back to `"NF2217"`.

**User-visible symptom:** Map sector label and panel title show "NF2217" while RouteExplainer card shows "NF2217-2218" — inconsistent naming for the same road segment.

**Fix:** Update `scripts/resolve-annotations.js` line 28 from `name: 'NF2217'` to `name: 'NF2217-2218'`, then re-run pipeline to regenerate all downstream files.

### 2. generate-og-image.js Not in Build Pipeline

**Severity:** Low — current build works, but no automated regeneration path
**Location:** `scripts/pipeline.js` (missing entry), `scripts/generate-og-image.js` (exists but orphaned)

The OG image script exists and `public/og-image.jpg` is correct on disk (1200x630 JPEG). However, `generate-og-image.js` is not registered in `pipeline.js`. If the hero image changes or `og-image.jpg` is deleted, a developer must manually run `node scripts/generate-og-image.js`. This is a pipeline completeness gap, not a build-breaking issue.
